# Настройка конфига

1. Скопируйте `config.example.json` в `config.json` (тот же каталог).
   `config.json` в `.gitignore` — не коммитится, содержит токены.
2. По умолчанию скилл работает без единого токена — все источники, для
   которых это возможно, идут по HTML/парсинг-fallback пути. Токен hh.ru
   повышает надёжность и полноту данных о работодателе, но не обязателен.

## Токен hh.ru (опционально)

1. Зарегистрируйте приложение на https://dev.hh.ru/ — раздел «Мои
   приложения» → «Создать приложение».
2. Тип приложения — «Работодатель» или «Все данные» в зависимости от того,
   к чему нужен доступ; для чтения публичных данных о компаниях достаточно
   базового доступа.
3. Получите `access_token` по OAuth-флоу, описанному в документации
   dev.hh.ru (client_credentials или authorization_code — в зависимости от
   типа приложения).
4. Впишите токен в `config.json`:
   ```json
   { "hh": { "api_token": "ВАШ_ТОКЕН", "prefer_api": true } }
   ```

Без токена `hh_client.py` при `prefer_api: true` попробует `api.hh.ru`,
получит 403 (известное ограничение — блокировка по IP дата-центра, см.
`../SKILL.md`) и молча перейдёт на HTML-парсинг. Это ожидаемое поведение,
не ошибка настройки.

## Остальные поля конфига

См. `config.example.json` — там же дефолты. Основные:

- `http.per_domain_delay_sec` — вежливая пауза между запросами к одному
  домену в рамках одного прогона. Увеличьте, если источник начал часто
  отдавать 403/429.
- `report.insights_period_months` — период, за который модуль 05 собирает
  «ключевые инсайты» (блок 2 отчёта).
- `report.max_persons` — сколько персон максимум включать в отчёт по одной
  компании.
- `paths.cache` / `paths.output` — относительно корня скилла.

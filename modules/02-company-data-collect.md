# 02 — Company Data Collect

**Вход:** `{company_name, site, hh_url}` из модуля 01.
**Выход:** структурированные факты о компании, каждый — с URL источника.

## Что делать

1. **Используй `collect_company.py` — один вызов вместо отдельных
   `hh_client.py`/`site_crawler.py`/`habr_client.py`/`media_search.py`.**

   ```
   python scripts/collect_company.py --company "<company_name>" --site <site> --hh-url <hh_url>
   ```

   Это не новая логика поверх старой — тот же код, вызванный напрямую
   (импорт функций, не subprocess), с одним объединённым JSON-ответом
   вместо 5+ отдельных. Дополнительный, а не побочный эффект: заодно
   закрывает этап 1 модуля 03 (широкий поиск ЛПР + обязательный разбор
   найденных ростер-страниц) — это уже встроено в скрипт, не отдельный
   шаг, который можно забыть выполнить. Проверено на реальном кейсе
   (Вебпрактик): нашёл «Алина Нагабедян — Менеджер по персоналу», которого
   не находили несколько ручных прогонов подряд ранее в тот же день —
   потому что ручной путь требовал не забыть найти и разобрать
   ростер-страницу отдельным шагом, а здесь это гарантированно происходит.

   Если у компании есть альтернативные домены того же субъекта (см.
   `modules/01-company-resolve.md` п.4c) — передай их через
   `--site-alternates "url1,url2"`, оба будут обойдены.

   Старые отдельные скрипты (`hh_client.py`, `site_crawler.py`,
   `habr_client.py`, `media_search.py`) никуда не делись и остаются
   рабочим способом получить один конкретный источник точечно — например,
   при дозапросе `--fetch-vacancy-contacts` отдельно от остального, или
   когда нужен только один источник для проверки конкретного факта.

2. Собери из ответа `collect_company.py` (`company_profile`, `vacancies`):
   сферу деятельности, отрасль, регион, вакансии, значимые факты (штат,
   возраст компании, аккредитации, статусы).

   **Численность штата — приоритет источников, не первое попавшееся
   число.** Найдено на реальном кейсе (RED SOFT): в отчёт попала грубая
   вилка «201–500 человек» с постороннего поста на habr.com, хотя
   собственный сайт компании называет другую (заметно большую) цифру, а
   независимый реестр (rusprofile-подобные источники через media_search)
   — третью, причём растущую год к году. Порядок приоритета: (1) прямое
   утверждение на сайте компании (`site_crawler.py`, страница «О
   компании») — обычно самое свежее и осознанно опубликованное; (2)
   официальный реестр юрлиц с датой среза; (3) сторонние агрегаторы/посты
   (habr.com, СМИ) — только если (1) и (2) недоступны, и с пометкой, что
   это оценка, а не официальная цифра. **Если источники расходятся —
   не выбирай молча одну цифру: приведи диапазон или обе цифры с датами
   и источниками**, это даёт пользователю материал для проверки вместо
   ложного ощущения точности.

3. **Каждый факт сохраняется вместе с URL источника — без этого он не
   попадёт в отчёт.** Это не стилистическое требование: отчёт без ссылок
   бесполезен для проверки перед outreach (п.3.3 ТЗ). Если скрипт вернул
   поле в `warnings` как ненайденное — это поле в отчёт не идёт (не
   заполняется приблизительно, не берётся из общих знаний о похожих
   компаниях).

4. Если `collect_company.py` вернул `ok: false` или часть полей пустая —
   это не повод останавливать модуль. Внутри он уже не роняет весь сбор
   из-за одного недоступного источника (hh.ru может не сработать, а сайт
   — сработает, и наоборот) — зафиксируй, что конкретно недоступно, по
   `warnings` в ответе, и продолжи с тем, что есть.

5. **Как реально происходит отбор в компанию — отдельный, приоритетный
   блок исследования, не факультативный.** По прямому запросу
   пользователя после сравнения прогонов: этапы собеседования, что
   спрашивают, сколько длится, довольны ли кандидаты процессом — сильнее
   как контекст для outreach, чем общие факты о компании.

   ```
   python scripts/media_search.py --query-set hr_process --company "<company_name>" --limit 20
   ```

   Если среди результатов есть `dreamjob.ru/employers/<id>` — разбери
   отдельно, это единственный источник в скилле, который даёт
   структурированное описание процесса отбора (число этапов, формат,
   вопросы на собеседовании), а не общие слова о компании:

   ```
   python scripts/dreamjob_client.py --company-url "<найденный URL>"
   ```

   **Эпистемический статус этих данных — не такой, как у остальных
   блока 1.** Это анонимные отзывы отдельных людей, не факт о компании.
   Каждое утверждение отсюда в отчёте обязано быть в форме «по отзыву
   кандидата/сотрудника на Dream Job», не «в компании трёхэтапный отбор»
   — второе представляет мнение одного человека как установленный факт
   (см. anti-patterns.md). Один отзыв — не статистика: если отзывов
   несколько и они расходятся (один говорит «1 этап», другой «3 этапа»),
   приводи это расхождение, а не выбирай один вариант как более
   вероятный.

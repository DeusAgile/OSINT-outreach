# 04 — Digital Footprint

**Вход:** `persons[]` из модуля 03 (уже прогнанные через `entity_resolve.py`).
**Выход:** для каждой персоны — публикации, выступления, комментарии,
профили, каждый факт со ссылкой.

## Что делать

Для каждой персоны из модуля 03 (используй `name_normalized` и
`name_variants` — поиск по всем вариантам написания повышает recall):

1. Вызови источники с `category: person_mentions`:

   ```
   python scripts/habr_client.py --person <username>   # если известен логин
   python scripts/tg_channel.py --channel <username>   # если известен канал
   python scripts/tenchat_client.py --profile <username>
   python scripts/media_search.py --query-set person_mentions --company "<company>" --person "<person>" --limit 20
   ```

2. **Атрибуция: перед записью факта проверь по выходу `entity_resolve.py`,
   что это тот же человек, а не однофамилец, и что аккаунт личный, а не
   корпоративный.** Конкретно:
   - у найденной публикации/профиля должно быть основание для привязки к
     той же персоне (совпадение имени с учётом `name_variants`, контекст
     упоминания компании);
   - если `company_link.type` у персоны — `"none"` (нет подтверждённой
     привязки к компании), не приписывай ей находки, где компания не
     упоминается явно — иначе это ровно тот тёзка, от которого
     предостерегает anti-patterns.md;
   - корпоративный аккаунт компании (публикует от лица бренда, не от
     первого лица) — не личный цифровой след, не записывай его сюда.

3. **Отдельно от общих «публичных страниц» — прямой канал связи.**
   Найдено на реальном кейсе (WMX): черновики были сгенерированы для
   человека, у которого в блоке 4 были только read-only упоминания
   (профиль эксперта на AM Live, интервью TAdviser) — ни личного email, ни
   Telegram-хендла, то есть физически некуда отправить готовый черновик.
   Отчёт это не флагировал явно, черновик получился формально готовым, но
   практически бесполезным.

   Поэтому для каждой персоны заведи отдельное поле `contact_channel`:
   - `{"type": "email", "value": "имя@домен"}` — из `hh_client.py`
     (`--fetch-contacts`), `site_crawler.py` (контакты на сайте), или
     `habr_client.py --company` (`profile.contacts.email`, если похож на
     личный — см. `modules/03-lpr-search.md`);
   - `{"type": "telegram", "value": "@handle"}` — из `site_crawler.py`
     (ссылки t.me на сайте), `tg_channel.py` (если у персоны есть
     собственный канал, не корпоративный);
   - `{"type": "none"}` — если ни то, ни другое не нашлось. Это не повод
     скрывать находку из отчёта (человек всё равно попадает в блок 3 как
     ЛПР), но это обязано остановить автоматическую генерацию черновика
     в модуле 06 — см. `modules/06-outreach-drafts.md`, новый шаг 1b.

4. Каждый факт цифрового следа — `{summary, url, source}`. Пустой
   результат по персоне — нормальный исход, не заполняется общими фразами.

## Известное ограничение

`media_search.py` в текущей среде может возвращать пустой результат из-за
анти-бот блокировки поисковика с IP дата-центра (см. `config/sources.md`).
Пустой результат отсюда — не доказательство отсутствия цифрового следа,
пометь это как ограничение источника, а не как факт о персоне.
